# 연구보고서형 톤 (민트/딥틸)

머신러닝 연구보고서 레퍼런스 덱에서 추출한 수치. 이 문서의 값만으로 톤이 재현되므로, 매번 샘플 이미지를 열어볼 필요가 없다.

## 캔버스

원본은 20 × 11.25 in (1920×1080 기준 16:9). 작업은 1280×720으로 하고, 아래 크기는 모두 1280×720 환산값이다.

## 색

| 역할 | hex | 쓰이는 곳 |
|---|---|---|
| 본문·제목 | `#0F3537` | 모든 제목과 본문 텍스트, 하단 푸터 바 배경 |
| 강조 | `#037A76` | 카드 제목, 라벨, 차트 주계열, 아이콘 선 |
| 민트 1 | `#ACD9C9` | 아이콘 원형 배경, 표지 서브타이틀 알약 |
| 민트 2 | `#A2D7CA` | 차트 보조 계열 |
| 민트 3 | `#D1ECE1` | 좌측 하이라이트 카드 배경, 하단 띠 배경 |
| 카드 | `#FFFFFF` | 콘텐츠 카드 |
| 구분선 | `#CDCECD` | 표 구분선, 얇은 룰 |

배경은 흰색에 아주 옅은 민트 그라데이션, 그리고 **분자 네트워크 패턴**(선+점)이 모서리에 깔린다. 패턴은 항상 콘텐츠 뒤 가장자리에만 있고 가운데를 침범하지 않는다.

강조색이 하나가 아니라 **딥틸 → 틸 → 민트 3단계 그라데이션 팔레트**로 움직이는 게 이 톤의 특징이다. 차트 계열도 이 순서로 쓴다.

## 타입

**Libre Franklin** (Regular / SemiBold / Bold). Google Fonts, OFL 라이선스라 무료 사용·재배포 가능.

| 용도 | 크기 | 비고 |
|---|---|---|
| 표지 제목 | 70px | Regular, 3줄까지 |
| 슬라이드 제목 | 48px | Regular, **중앙 정렬** |
| 리드문 | 20px | 제목 바로 아래 한 줄 |
| 카드 제목 | 17px | 강조색, 중앙 정렬 |
| 본문 | 14px | |
| 푸터·캡션 | 10px | 대문자 자간 넓게 |

**한글 주의:** Libre Franklin은 한글 글리프가 없다. 한글 자료면 본문을 Pretendard로 두고 숫자·영문만 Libre Franklin을 쓰거나, 전부 Pretendard로 통일해야 한다. 섞어 쓰면 자간과 굵기가 어긋난다.

## 레이아웃 골격

```
        ┌─────────────────────────────────┐
        │        제목 (중앙, 48px)          │
        │     리드문 한 줄 (중앙, 20px)      │
        ├──────┬────────────┬─────────────┤
        │ 카드 │   카드      │    카드      │  상단 3열 (비율 1:1.6:1 등 가변)
        ├──────┴────────────┴─────────────┤
        │  가로 띠 카드 (3~5칸 아이콘+텍스트) │
        ├─────────────────────────────────┤
        │ 섹션명            PAGE 04        │  딥틸 푸터 바
        └─────────────────────────────────┘
```

- 카드: 흰 배경, 모서리 반경 약 16px, 아주 옅은 그림자, 테두리 없음
- 하단 띠는 민트 3 배경 또는 흰 배경 + 세로 구분선
- 푸터 바는 딥틸 배경에 흰 글씨, 좌측 섹션명·우측 `PAGE NN`
- 아이콘: 민트 1 원형 배경 + 강조색 라인 아이콘, 지름 약 32px

## 차트

- 딥틸 → 틸 → 민트 순서로 계열 배정, 강조 계열만 진한 색
- 격자선은 가로만 옅게, 세로 격자·테두리 없음
- 도넛, 라인, 가로 막대, 레이더 모두 등장. 축 라벨 10px

## 이 톤의 성격

정보 밀도가 높은 **포스터형**이다. 한 장에 카드 6~8개, 아이콘 10개 이상이 들어간다. 발표 중 구두 설명을 전제하지 않고 **혼자 읽어도 이해되도록** 만든 형식이라, 연구 요약·리서치 리포트·제출용 자료에 맞는다. 5분 발표용으로 쓰면 청중이 슬라이드를 읽느라 발표자를 안 본다.

## 맥킨지 문법과 충돌하는 지점

이 샘플은 컨설팅 덱 문법과 방향이 반대다. 섞으면 둘 다 무너지므로 하나를 골라야 한다.

| 항목 | 이 톤 | 맥킨지 |
|---|---|---|
| 제목 | 명사형 정보 제목, 중앙 정렬 ("Study Design at a Glance") | 명사형 정보 제목, 좌측 정렬 |
| 결론 위치 | 마지막 요약 장 | 3번째 장에서 선언 |
| 장식 | 배경 패턴, 아이콘, 둥근 카드 | 전부 제거 |
| 정보 밀도 | 한 장에 카드 6~8개 | 한 장에 메시지 1개 |
| 키커 | 없음 | 모든 장 하단 필수 |

절충한다면 **시각 톤은 이 샘플, 논리는 맥킨지**가 가능하다. 제목을 명사형 정보 제목으로 좌측 정렬하고, 하단 띠 카드 자리를 핵심 키커로 쓰면 된다. 다만 정보 밀도는 낮춰야 한다 — 카드 8개에 하나의 해석 문장을 붙이면 그 문장이 무슨 근거를 가리키는지 알 수 없다.

## 레이아웃 목록

골격은 `assets/research-slides.html`. 아래 셋만 쓰고 새로 만들지 않는다.

| 이름 | 용도 |
|---|---|
| `layout-cover` | 표지 — 아이브로우 + 제목 + 민트 알약 부제 |
| `g-3` (1 : 1.6 : 1) | 개요형 — 좌 요약카드 / 중앙 도식 / 우 지표 + 하단 띠 |
| `g-even` (1 : 1 : 1) | 요약·상세형 — 출처 / 결론 / 연구정보 |

카드 안에서 반복되는 요소는 `.row`(원형 아이콘 + 텍스트), `.bars`(가로 막대), `.strip`(하단 띠), `.foot`(딥틸 푸터 바) 넷이다.
