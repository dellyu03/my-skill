# PPT Design Skill

발표자료(PPT·슬라이드)의 **구조(설계서)** 와 **디자인(레퍼런스 HTML 3장)** 을 함께 만들어주는 Claude Code 스킬입니다. 20장짜리 완성 덱을 한 번에 뽑아내는 대신, 논리가 확정된 설계서와 그대로 복제해서 채우면 되는 레퍼런스 슬라이드 3장을 만들어 줍니다.

## 이 스킬이 해결하는 문제

1. **목적을 모른 채 만든다.** 공모전 심사위원과 과목 교수는 같은 프로젝트를 봐도 다른 것을 평가합니다. 이 스킬은 용도(과제·공모전·연구보고서·이력서 등)를 먼저 판별해 순서와 강조 배분을 다르게 잡습니다.
2. **디자인과 논리를 매번 새로 만들어서 뒤죽박죽이 된다.** 색·폰트·레이아웃을 고정 토큰(`:root` CSS 변수)과 정해진 레이아웃 클래스로 못박아 자유도를 없앱니다.

## 사용법

별도 명령어 없이, 아래와 같은 요청을 하면 자동으로 트리거됩니다.

- "PPT 만들어줘", "발표자료 초안 짜줘"
- "슬라이드 구성 짜줘", "발표 준비 도와줘"
- "이 내용 발표용으로 정리해줘", "보고서를 슬라이드로 만들어줘"
- 기존 슬라이드를 보여주며 "이 덱 구성/디자인 검토해줘"

### 진행 순서

1. **브리프 추론** — 대화·파일·기억에서 용도(과제/공모전/연구보고서/이력서 등)를 먼저 추론하고, 추론한 기본값(평가자·시간·장수·톤)을 한 줄로 제시합니다. 다섯 개를 한꺼번에 묻지 않고, 기본값으로 못 채우는 것(발표 시간, 심사 기준 유무 등)만 확인합니다.
2. **톤 결정** — 컨설팅형 / 제안서형 / 연구보고서형 중 하나를 고르고 색 프리셋을 제안합니다. 톤은 섞지 않습니다.
3. **설계서 승인** — 슬라이드별 레이아웃·제목·핵심 메시지·근거를 표로 먼저 정리해 확인받습니다. 디자인보다 논리가 우선입니다.
4. **레퍼런스 3장 생성** — 표지 / 핵심 요약(또는 목차) / 본문 대표 1장을 실제 HTML로 만들어 보여줍니다. 나머지 장은 이 3장을 복제해서 채우면 됩니다.
5. 필요하면 `.pptx`로 변환하거나, 브라우저 인쇄로 PDF를 바로 뽑습니다.

### 수정 요청

만든 뒤에도 자연어로 계속 다듬을 수 있습니다.

- "색/분위기 바꿔줘" → `:root` 변수만 교체
- "이 장 구성 바꿔줘" → 레이아웃 클래스만 교체
- "장 추가해줘" → 기존 장을 복제, 새 스타일은 만들지 않음
- "제목이 밋밋해" → 명사형 정보 제목으로 재작성
- "전체 덱으로 만들어줘" → 이때만 설계서 기준 전체 생성

## 새 템플릿 추가하기

원하는 디자인 템플릿(이미지, PPT, PDF, HTML 등)이 있다면 파일을 올리고 **"이 템플릿도 추가해줘"** 라고 요청하면 됩니다. 스킬이 원본을 그대로 복제하는 대신, 다음을 자동으로 수행해 기존 톤들과 동일한 형식으로 맞춰줍니다.

1. 템플릿에서 색상 팔레트(hex), 서체, 여백·간격, 레이아웃 패턴을 추출합니다.
2. 기존 톤(컨설팅형·제안서형·연구보고서형)의 변형인지, 완전히 새로운 톤인지 확인받습니다.
3. **기존 톤의 변형**이면 해당 `references/*.md`에 새 색상 프리셋으로 추가하고, 필요 시 골격 파일(`assets/*.html`)에 레이아웃 변형을 더합니다.
4. **새로운 톤**이면 `references/tone-{이름}.md`와 `assets/{이름}-slides.html`을 기존 문서·골격과 같은 구조로 새로 만들고, `SKILL.md`의 톤 표에 등록합니다.
5. 어느 경우든 `:root` 토큰 + `section` 골격, 1280×720 고정 캔버스, 인라인 style 금지, 8px 배수 간격, 서체 2종 이하 같은 고정 규칙은 그대로 유지됩니다. 즉 템플릿의 겉모습만 가져오고, 수정 비용을 낮추는 내부 구조는 이 스킬의 규칙을 따릅니다.
6. 업로드한 원본 파일은 참고용으로 `assets/samples/`에 보관됩니다.

이후에는 새로 추가한 템플릿도 다른 톤과 동일하게 "이 톤으로 만들어줘"라고 지정해서 쓸 수 있습니다.

## 폴더 구조

```
ppt-design-skill/
├── SKILL.md                     # 스킬 동작 정의 (Claude가 읽는 지침 본문)
├── references/                  # 용도별·톤별 세부 가이드
│   ├── project.md                #   과제·캡스톤 발표
│   ├── contest.md                #   공모전·해커톤
│   ├── report.md                 #   동아리 활동 보고서
│   ├── resume.md                 #   이력서·포트폴리오
│   ├── mckinsey.md                #   컨설팅형 톤 (색·타입·레이아웃)
│   ├── tone-proposal.md          #   제안서형 톤
│   └── tone-research.md          #   연구보고서형 톤
└── assets/
    ├── mckinsey-slides.html      # 컨설팅형 골격 (표지/요약/근거)
    ├── proposal-slides.html      # 제안서형 골격 (표지/목차/본문)
    ├── research-slides.html      # 연구보고서형 골격 (표지/카드/요약)
    └── samples/                  # 참고용 렌더 이미지·업로드 원본
```

## 디자인 원칙 (요약)

- 색은 톤 문서에 정의된 팔레트만 사용하고, 강조색은 덱 전체에서 한 가지 의미로만 씁니다.
- 서체는 2종 이하, 한글 자료는 Pretendard로 통일합니다.
- 제목은 기본적으로 명사형 정보 제목("응답 지연 개선 결과")이고, 서술형 문장으로 끝내지 않습니다.
- 간격은 8px 배수만 사용합니다.
- 모든 디자인 값은 HTML 최상단 `:root` 변수에 모아, 색 변경이 변수 몇 줄 교체로 끝나도록 합니다.

세부 규칙과 각 용도·톤별 대표 감점 요인은 `SKILL.md`와 `references/` 문서를 참고하세요.
